## 阶段 1：投递分析

用户提供一个岗位的 JD，Claude 完成公司调研、JD 解析和简历匹配分析。

### 执行步骤

1. **公司调研** — 使用 WebSearch 搜索该公司的：
   - 主营业务、行业地位、融资情况
   - 最新动态（新闻、产品发布）
   - 技术栈和业务方向
   - 团队规模和面试岗位所在部门

2. **JD 解析** — 从 JD 中提取：
   - 必备技能 / 加分技能
   - 经验年限要求
   - 业务领域关键词
   - 薪资范围

3. **简历匹配分析** — 对比用户简历与 JD：
   - 列出匹配项和缺失项
   - 计算匹配度
   - 给出通过率预估
   - 简历定制建议（需突出什么、弱化什么）

4. **生成投递分析.md** — 将以上内容合并写入：

   ```markdown
   # 投递分析 -- {公司} {岗位}

   ## 基本信息
   - 公司：{公司名}
   - 岗位：{岗位名}
   - 薪资：{范围}
   - 经验要求：{年限}
   - 分析日期：{YYYY-MM-DD}

   ## 公司调研

   ### 公司概况
   - 主营业务：...
   - 行业地位：...
   - 融资情况：...
   - 团队规模：...

   ### 最新动态
   - ...

   ### 技术与业务方向
   - 技术栈：...
   - 业务方向：...

   ## JD 技能拆解

   ### 必备技能
   - ...

   ### 加分技能
   - ...

   ### 业务领域
   - ...

   ## 简历匹配分析

   ### 匹配项
   - ...

   ### 缺失项
   - ...

   ### 匹配度评估
   - 技能匹配度：{X%}
   - 通过率预估：{X%}

   ### 简历定制建议
   - 需突出：{哪些项目经验}
   - 需弱化：{哪些不相关内容}
   - 建议新增：{哪些关键词}
   ```

### 产出

- `{岗位}-{公司}/投递分析.md`

## 阶段 2：定制简历

### 目标

针对具体 JD 定制简历，提高简历通过率。

### 前置条件

- 已完成阶段 1（有 `投递分析.md` 中的定制建议）
- 有基础简历可用（用户提供或当前目录下已有）

### 执行步骤

1. **读取投递分析** — 获取阶段 1 中的简历定制建议
2. **定制简历** — 基于匹配分析修改简历：
   - 调整项目经验的描述顺序和措辞
   - 将 JD 关键词自然融入
   - 突出最匹配的项目和技能
   - 使用 `docx` 技能输出 .docx 格式
   - 使用 `pdf` 技能导出 PDF 版本

### 简历定制要点

- **STAR 法则**描述项目：Situation → Task → Action → Result
- **量化成果**：用数字说话（提升 X%、处理 Y 量级、服务 Z 用户）
- **关键词密度**：JD 中的核心技术词至少出现 2-3 次
- **篇幅控制**：1-2 页，不超过 2 页

### 产出

- `{姓名}-{岗位}-{公司}-简历.docx`
- `{姓名}-{岗位}-{公司}-简历.pdf`

## 阶段 3：HR 初面

### 目标通过率：60%

HR 初面主要考察基本素质、沟通能力和岗位匹配度。准备充分可以将通过率提升到 80%+。

### 生成 `HR初面准备.md`

1. **自我介绍**（3 分钟版 + 1 分钟版）
   - 结构：我是谁 → 做过什么 → 为什么适合这个岗位
   - 针对该岗位的侧重点

2. **公司了解**
   - 公司主营业务、行业地位
   - 最近动态（新闻、产品发布）
   - 面试岗位所在部门/团队

3. **高频问题准备**

   | 问题类别 | 典型问题 |
   |---------|---------|
   | 基本信息确认 | 简历上的经历确认、学历验证 |
   | 求职动机 | 为什么选择我们？为什么投这个岗位？ |
   | 职业规划 | 未来 3-5 年规划？想往什么方向发展？ |
   | 离职原因 | 为什么离开上一家公司？（避免负面评价） |
   | 薪资期望 | 当前薪资？期望薪资？（给出合理区间） |
   | 到岗时间 | 最快什么时候能入职？ |
   | 其他 offer | 还在面试其他公司吗？ |

4. **反问环节** — 准备 2-3 个向 HR 了解的问题

### 文档格式

```markdown
# HR 初面准备 -- {公司} {岗位}

## 自我介绍

### 3 分钟版
...

### 1 分钟版
...

## 公司了解
...

## 高频问答准备

### Q1: 为什么选择我们？
**要点**：...
**参考回答**：...

### Q2: ...
...

## 反问准备
1. ...
2. ...
```

### 模拟面试模式

扮演 HR 角色，逐一提问上述高频问题，每轮：
- 提问 → 等用户回答 → 给出反馈和改进建议
- 反馈维度：内容完整性、表达清晰度、是否有踩坑

## 阶段 4：技术一面

### 目标通过率：80%

技术一面侧重基础知识和项目经验的深度考察。

### 生成两份文档

#### STAR面经.md

基于简历中的项目经验，为每个核心项目生成 STAR 叙述：

```markdown
# STAR 面经 -- {公司} {岗位}

## 项目 1：{项目名}

**S（情境）**：...
**T（任务）**：...
**A（行动）**：...
  - 技术决策 1：{为什么选这个方案}
  - 技术决策 2：{踩过的坑和解决方式}
**R（结果）**：...
  - 量化指标：{性能提升/用户增长/成本降低}

### 可能的追问
- Q: 为什么不选 XX 方案？
- Q: 这个项目中遇到最大的挑战是什么？
...

## 项目 2：{项目名}
...
```

#### 技术一面准备.md

根据 JD 技术栈生成考点清单：

```markdown
# 技术一面准备 -- {公司} {岗位}

## 考点清单

基于 JD 分析，以下为高概率考点：

| # | 考点 | 重要性 | 掌握程度 |
|---|------|--------|---------|
| 1 | ... | 高 | 待评估 |
| 2 | ... | 高 | 待评估 |

## 需深入学习的主题

以下主题建议使用 `zjk-mastery` 技能进行系统学习。学完后回到对话告知掌握情况，以便调整面试准备重点。

| # | 主题 | 对应 JD 考点 | 紧急程度 |
|---|------|-------------|---------|
| 1 | {主题} | {考点} | 高/中/低 |
| 2 | {主题} | {考点} | 高/中/低 |
```

### 模拟面试模式

扮演技术面试官角色。开始前先请用户提供通过 `zjk-mastery` 学习的 AI 笔记内容（可直接粘贴，或提供文件路径让 Agent 读取）。Agent 基于这些笔记内容来出题、追问和反馈。

基于笔记内容针对性提问：
- **笔记中掌握扎实的**：快速验证 1-2 个关键问题，确认理解深度
- **笔记中表述模糊或未涉及的**：多追问深挖，帮助发现盲区

流程：
1. **项目深挖**（15 分钟）：围绕简历项目追问技术细节
2. **基础知识**（15 分钟）：基于 AI 笔记内容差异化提问
3. **手撕代码**（可选，10 分钟）：1-2 道算法题
4. 反馈：每个环节给出评分和改进建议

## 阶段 5：技术二面

### 目标通过率：80%

技术二面通常由更高级别的面试官进行，侧重系统设计、架构能力和技术深度。

### 生成 `技术二面准备.md`

1. **一面复盘** — 回顾一面被问到的问题和回答不够好的地方

2. **系统设计准备**
   - 根据岗位方向准备 2-3 个系统设计题
   - AI 方向：设计一个 RAG 系统 / 设计一个 Agent 架构 / 设计推荐系统
   - 后端方向：设计高并发 API / 设计消息系统 / 设计缓存策略

3. **STAR 面经深化**
   - 从技术一面的 STAR 扩展
   - 增加架构层面的思考
   - 准备技术决策的权衡分析

### 文档格式

```markdown
# 技术二面准备 -- {公司} {岗位}

## 一面复盘
- 被问到的问题：...
- 回答不够好的地方：...

## 系统设计

6. 权衡分析
```

## 阶段 6：HR 终面

### 目标通过率：80%

终面通常由部门负责人或 HRD 进行，侧重综合素质、文化匹配和薪资谈判。

### 生成 `终面准备.md`

1. **综合素质准备**
   - 领导力 / 团队协作案例
   - 压力应对 / 冲突解决案例
   - 自我认知（优势、不足、改进计划）

2. **薪资谈判准备**
   - 调研市场行情（同岗位同城市薪资范围）
   - 确定底线和期望值
   - 准备谈判话术

   **谈判策略**：
   - 先让对方出价
   - 用市场数据支撑期望值
   - 不急于接受第一个 offer
   - 考虑总包（base + bonus + 股票 + 福利）

3. **反问准备**（对部门负责人的高质量问题）
   - 团队当前面临的最大挑战
   - 技术栈演进方向
   - 团队文化和工作方式
   - 入职后的期望和成长路径

4. **高频问题**

   | 问题 | 回答要点 |
   |------|---------|
   | 最大的成就/失败 | STAR 法则，强调从失败中学到的 |
   | 为什么选你 | 匹配岗位的核心竞争力 |
   | 你的职业规划 | 与公司/岗位发展方向一致 |
   | 期望薪资 | 给区间，说明理由 |
   | 最快到岗时间 | 实事求是 |

### 文档格式

```markdown
# 终面准备 -- {公司} {岗位}

## 综合素质

### 成就案例
...

### 挫折案例
...

### 优势与不足
...

## 薪资谈判

### 市场行情
- 同岗位同城市范围：...
- 数据来源：...

### 谈判策略
- 底线：...
- 期望值：...
- 话术准备：...

## 高频问答准备
...

## 反问准备
1. ...
2. ...
```

### 模拟面试模式

扮演 HRD / 部门负责人：
1. **综合素质**（15 分钟）：行为面试题
2. **文化匹配**（10 分钟）：价值观、工作方式
3. **薪资沟通**（5 分钟）：模拟谈薪
4. 反馈：综合素质评分 + 谈薪策略建议

## 模拟面试指引

### 通用规则

- 面试前明确：面试类型（HR/技术一面/技术二面/终面）、目标公司、岗位方向
- 逐题提问，等用户回答后再问下一题
- 每题给出反馈：内容、表达、改进建议
- 全部结束后给出整体评估和通过率预估

### 评估维度

| 维度 | 权重 | 评分 |
|------|------|------|
| 内容完整度 | 30% | 1-5 |
| 技术准确性 | 25% | 1-5 |
| 表达清晰度 | 20% | 1-5 |
| 逻辑结构 | 15% | 1-5 |
| 自信度 | 10% | 1-5 |

## 面经复盘指引

### 适用场景

用户面完试后，帮助复盘分析，为后续面试提供改进方向。

### 执行步骤

1. **收集信息** — 询问用户：
   - 面试的公司和岗位
   - 被问到的问题（尽量回忆）
   - 自己回答的情况
   - 面试官的反应/反馈

2. **问题分析** — 逐题分析：
   - 面试官考察意图
   - 用户回答的优点
   - 可以改进的地方
   - 参考答案/更好的回答方式

3. **模式识别** — 从所有面试中总结：
   - 高频考点
   - 用户普遍薄弱的领域
   - 需要重点加强的方向

4. **行动计划** — 输出改进计划：
   - 短期（下次面试前）：重点复习哪些
   - 中期（1-2 周）：补充学习哪些知识
   - 建议使用哪个联动技能来系统提升

5. **写复盘文档** — 保存到 `复盘/` 目录：

   ```markdown
   # {面试类型}复盘 -- {公司} {岗位}

   > 日期：{YYYY-MM-DD}

   ## 被问到的问题

   ### Q1: {问题}
   - 我的回答：...
   - 面试官反应：...
   - 考察意图：...
   - 改进建议：...
   - 参考回答：...

   ### Q2: ...

   ## 总结

   ### 做得好的
   - ...

   ### 需要改进的
   - ...

   ### 行动计划
   - 短期：...
   - 中期：...
   ```
